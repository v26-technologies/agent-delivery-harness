# Installed resource applicability is separate from check reuse

This candidate adds capture and native successful-attempt projection retention, not an activated selection path. A committed-source snapshot cannot describe installed package manifests, package resolution, directory membership or binary bytes. Observe those inputs only inside the invocation-owned dependency snapshot, retain their actual bytes and metadata, and verify the snapshot before and after observation. Caller-supplied JSON and a lockfile alone are not native resource authority.

A successful full-Git check remains bound to its original HEAD and prepared tree. Its attempt must stay ineligible for whole-check reuse after an unrelated commit. A separately versioned resource-applicability projection may compare the same named consumer's guarded source inputs and installed resource facts; it neither supplies `checks.passed` for another candidate nor grants arbitrary filesystem or executable-package permission. Native origin confirmation, current source applicability, health and normal invalidation still apply.

Use the existing snapshot acquisition path for both capture and execution. Capturing resources must allocate no check attempt and run no consumer command. Serialize preselection capture, drain accepted capture before execution/cleanup, and preserve per-worker ownership. The serial pool retains its existing consecutive-setup eviction behavior: a first adopter with one setup can share capture and execution; multiple setup keys need an explicit supported design, not a hidden cache or a promise that eviction no longer occurs.

Keep package exports, nearer-install refusal, complete requested-directory membership, actual binary bytes, and missing/link/size refusals. Replacing package resolution with literal root paths or replacing discovery with a fixed file list changes the behavior being tested. Existing configuration already forbids writable `node_modules` outputs; retain that single enforcement rather than add a redundant runtime guard.

The native coordinator derives source/setup authority from the configured consumer and both immutable source snapshots. It seeds a projection only after the actual command passes post-command snapshot verification, and only from the same snapshot object that supplied the capture. The allocator retains the actual execution HEAD separately from the unchanged full-Git attempt identity. Caller-supplied contexts cannot seed projections; a newer unqualified pass fences older projection history. Reuse the already captured candidate reader and inventory rather than enumerate the candidate again for resource binding.

The focused primitive, observer, storage and pool fixtures prove their component boundaries. An unrelated-commit fixture now demonstrates resource matching while the old full-Git attempt stays stale; it does not yet establish gate admission or selected-command omission. The remaining native gate/portable evidence integration, relevant-restoration lifecycle and actual adopter proof are still required before default omission or ticket completion. Source-only planning must remain install-free, and resource setup must not accidentally add installations to preparation or record-neutral refresh paths that did not previously need them.
