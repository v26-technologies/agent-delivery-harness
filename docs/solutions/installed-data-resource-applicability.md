# Installed resource applicability is separate from check reuse

This candidate adds an opt-in native applicability path; no repository adopter is activated by the producer change alone. A committed-source snapshot cannot describe installed package manifests, package resolution, directory membership or binary bytes. Observe those inputs only inside the invocation-owned dependency snapshot, retain their actual bytes and metadata, and verify the snapshot before and after observation. Caller-supplied JSON and a lockfile alone are not native resource authority.

A successful full-Git check remains bound to its original HEAD and prepared tree. Its attempt must stay ineligible for whole-check reuse after an unrelated commit. A separately versioned resource-applicability projection may compare the same named consumer's guarded source inputs and installed resource facts; it neither supplies `checks.passed` for another candidate nor grants arbitrary filesystem or executable-package permission. Native origin confirmation, current source applicability, health and normal invalidation still apply.

Use the existing snapshot acquisition path for both capture and execution. Capturing resources must allocate no check attempt and run no consumer command. Serialize preselection capture, drain accepted capture before execution/cleanup, and preserve per-worker ownership. The serial pool retains its existing consecutive-setup eviction behavior: a first adopter with one setup can share capture and execution; multiple setup keys need an explicit supported design, not a hidden cache or a promise that eviction no longer occurs.

Keep package exports, nearer-install refusal, complete requested-directory membership, actual binary bytes, and missing/link/size refusals. Replacing package resolution with literal root paths or replacing discovery with a fixed file list changes the behavior being tested. Existing configuration already forbids writable `node_modules` outputs; retain that single enforcement rather than add a redundant runtime guard.

The native coordinator derives source/setup authority from the configured consumer and both immutable source snapshots. It seeds a projection only after the actual command passes post-command snapshot verification, and only from the same snapshot object that supplied the capture. The allocator retains the actual execution HEAD separately from the unchanged full-Git attempt identity. Caller-supplied contexts cannot seed projections; a newer unqualified pass fences older projection history. Reuse the already captured candidate reader and inventory rather than enumerate the candidate again for resource binding.

The focused primitive, observer, storage and pool fixtures prove their component boundaries. The native lifecycle fixture demonstrates a real cold command, warm gate admission without another consumer command, portable record/verify without installation and restoration after resource DATA changes. The old full-Git attempt stays stale. Separate resource bindings flow through admission, manifest validation, records and portable verification; no passed no-command attempt is synthesized. Actual adopter proof, independent review and a verified local runtime artifact remain required before producer delivery and Athena activation. Source-only planning must remain install-free, and resource setup must not accidentally add installations to preparation or record-neutral refresh paths that did not previously need them.

Portable reconstruction must validate original guarded source authority as well as the original whole-check digest. A supplied-port negative case coherently changed an original reader, recomputed its full-Git input/profile and projection-origin digests, and still passed when only current/base guards were checked. Reconstruct the original two-snapshot source binding too, then require it to equal the retained applicability projection. Refusing this case preserves the distinction between a consistent execution identity and a qualified consumer.

A warm gate must not make record creation reinstall dependencies. The native same-candidate refresh fixture originally observed a third setup after cold+warm setup counts of two. Reconstruct the accepted current-candidate resource observation from existing evidence, retain strict record-neutral transport only, and recheck latest native origin precedence without installation. Changed deliverable candidates still require fresh capture; this is evidence reuse within the existing records, not an installed-resource cache.

Resolve conditional resources at the consumer execution stage. Capturing before an earlier different-setup check lets the serial pool legitimately discard the resource snapshot; the consumer then reinstalls and cannot seed a same-snapshot projection. Retain ordinary serial eviction and dispatch capture plus applicability/cold execution under the consumer worker's ordering instead. The distinguishing serial two-setup fixture must prove one resource setup, a seeded successful origin and omission on a later unrelated candidate. Portable request comparison uses normalized request/file/directory ordering while the declaration digest retains its original configuration identity.
